# Читаемые исходники с неизменным байткодом

## Область и критерий приёмки

Все 21 семейство из `workspace.json`: Classic DEX, CPMM, Uranus, X1000.
Работаем в `projects/`; опубликованные исходники в `reconstruction/` сохраняются.
Каждая порция принимается только при совпадении code cell hash **и всего
канонического BOC** с `oracles/`. Тесты поведения дополняют это сравнение.
Проверка не подставляет оригинальный BOC вместо результата компиляции.

Acton 1.2.1 запускает тесты. Исходники по-прежнему собираются Tolk 1.4.0 / FunC
0.4.4: смена компилятора уже меняет код. Порядок импортов, объявления вариантов
union, method ID, типы и порядок сериализации считаются частью совместимости.

## Образцы и источники

- Локальный образец Acton: `regression/fixtures/acton-sources/jetton-reference/contracts/`
  в корне репозитория: JettonMinter, JettonWallet, messages, storage, fees-management.
- [Официальный Jetton на Tolk](https://github.com/ton-blockchain/acton-contracts/tree/master/jetton-v2.1/contracts):
  названия запросов и уведомлений по действию, отдельные схемы сообщений и storage,
  именованные режимы отправки и ошибки.
- [Официальные opcode на FunC](https://github.com/ton-blockchain/jetton-contract/blob/main/contracts/op-codes.fc):
  символические константы операций; их значение записывается в hex.
- [TEP-74](https://github.com/ton-blockchain/TEPs/blob/master/text/0074-jettons-standard.md):
  проверка назначения стандартных операций и полей Jetton.
- [Реестр ABI TON](https://github.com/ton-blockchain/abis): вспомогательное соответствие
  DeDust opcode; сопоставляем с обработчиком и сериализацией нашего контракта.
- Реальные объявления stdlib: зафиксированный `@ton/tolk-js@1.4.0` и
  `libraries/func/stdlib.fc`. Новые API из шаблона Acton не переносятся вслепую.

Имена восстанавливаются по роли и подтверждённому формату. Это не утверждение об
исходных приватных именах автора. Один opcode без контекста не доказывает протокол.

## Правила нормализации

1. **Opcode — код операции сообщения.** Обычно это первые 32 бита тела. В FunC
   используем `OP_*`, в Tolk — именованную структуру сообщения либо `OP_*` при
   ручной сериализации. `queryId` — идентификатор запроса, а не opcode.
2. **Запрос и уведомление различаются.** `JettonTransfer`, `JettonInternalTransfer`,
   `JettonTransferNotification`, `JettonBurnNotification` — разные сообщения;
   `Sell` в кошельке и уведомление о продаже в master также различаются.
3. **Служебные биты не называем opcode.** `addr_none`, TL-B флаги сообщения,
   варианты Either/Maybe, версия storage и tag активации получают отдельные имена.
   Не заменяем пакет из 143 бит на поле из 32 бит: в первом есть ещё заголовок.
4. **Называем роли значений.** `opcode`, `queryId`, `jettonAmount`, `forwardTonAmount`,
   `senderOwner`, `recipientOwner`, `responseAddress`, `storage`, `messageBody`.
   Номер временной переменной не объясняет её назначение. Не придумываем назначение
   непроверенным полям только ради красивого имени.
5. **Стандартная библиотека предпочтительна.** Убираем локальный ASM-дубль, когда
   совпадают семантика, типы, порядок вычисления, стек и полученный BOC.
   `common.tolk` подключается Tolk автоматически; специализированные модули — через
   явный импорт (например, `@stdlib/gas-payments`, `@stdlib/tvm-dicts`).
6. **Null и optional не взаимозаменяемы без проверки.** Исторический физический
   слот иногда объявлен `cell`, хотя в TVM содержит null. Приведение и проверка
   сохраняются, пока смена типа не доказана компиляцией. `dict` и `cell?` имеют
   сходное представление, но разные API и правила проверки типов.
7. **ASM не маскируем.** Совместимые stdlib-вызовы заменяют дубли. Остаточные
   перестановки стека, границы времени жизни, CALLDICT/CALLXARGS и старые кодеки
   остаются явно обозначенными: равенство результата недостаточно для равенства
   инструкций. Перенос в другой файл сам по себе не считается устранением ASM.
8. **Константы вместо магических режимов.** Используем штатные `SEND_MODE_*` и
   `RESERVE_MODE_*`, сохраняя битовую комбинацию. Название ошибки выводим из
   конкретной проверки; одинаковый номер в разных обработчиках может иметь
   разный смысл.
9. **Упрощения отдельно от переименований.** Сначала переименовываем и проверяем
   BOC. Затем отдельно проверяем исчезновение временных переменных, bool/int
   переходов и замену кодеков. Не меняем ленивость разбора и порядок исключений.
10. **Отступы и пустые строки показывают структуру.** Вложенность — четыре пробела.
    Отделяем пустой строкой функции (включая ASM-хелперы), группы импортов,
    констант и globals. В обработчиках разделяем проверки, ветвления, начало
    разбора/сборки ячейки, запись состояния, отправку сообщения и возврат.
    Последовательные поля, импорты и связанные проверки оставляем вместе.
    Комментарий и аннотация остаются рядом с объявлением. Внутри строковых
    литералов, многострочного ASM и комментариев новые разделители не вставляем.
    Правила закреплены в `tools/format-spacing.mjs`: `npm run fmt` применяет их,
    а `npm run fmt:check` проверяет. Порядок импортов и объявлений сохраняется.

## Журнал проверки

Рабочий журнал дополняется по мере прохождения побайтовых проверок. Неудачная
проба не остаётся в исходниках. Итоговые команды: `npm run verify`.

### Отступы и разделение блоков — 2026-10-10

Плотные списки FunC ASM-хелперов разделены пустыми строками. В FunC и Tolk
визуально отделены этапы обработчиков: чтение, проверки, ветвления, сборка
сообщения, запись и возврат. Используется существующий отступ в четыре пробела;
форматтер сохраняет переносы аргументов и цепочек вызовов. Изменения исходников
добавляют только пустые строки, без замены токенов, строк ASM или значений.

Acton отвечает за форматирование Tolk с полным `--range` без сортировки импортов,
после него применяется разделение блоков. Для FunC оно встроено в форматтер
с проверкой неизменности токенов. Повторный запуск не добавляет новые отступы.

### X1000: stdlib, первая порция

Прямые вызовы stdlib вместо локального ASM: `sendRawMessage`, `blockchain.now`,
`blockchain.logicalTime`, `contract.getAddress`,
`contract.getOriginalBalanceWithExtraCurrencies`, `builder.hash`,
`isSignatureValid`, `builder.storeCoins`, `builder.storeMaybeRef`,
`builder.storeAddress`, `builder.storeSlice`, `slice.assertEnd`, `slice.skipBits`,
`slice.skipDict`. Проверка VM null выражается через `== null`, PUSHNULL — через
`null` с сохранением физического типа.

Замена `preloadMaybeDictionary` на `preloadDict` без приведения отклонена:
следующий код работает с cell, а stdlib возвращает dict. Простое удаление
локального `acceptExternalMessage` также недостаточно: его штатное объявление
находится в модуле `gas-payments`, требуется импорт.

Оба случая исправлены: `preloadMaybeRef()` возвращает исходный nullable-слот через
явный совместимый cast, а `gas-payments` импортируется непосредственно в файл
использования `acceptExternalMessage`. Оба варианта прошли сравнение всего BOC.

### Общий словарь сообщений

В `libraries/messages/opcodes.json` записаны **96** идентификаторов с источником
каждого имени. `tools/opcodes.mjs` генерирует константы для FunC и Tolk и проверяет
их согласованность. Каталог содержит только конкретно рассмотренные сообщения,
а не глобальную эвристику «один номер всегда означает один протокол».

В Classic именованные константы используются в диспетчерах, отправке сообщений,
callback и событиях. Например, ветка Factory `x_01 == 3395376462` стала
`opcode == OP_FACTORY_TRANSFER_OWNERSHIP`. В Tolk сохранены существующие именованные
структуры с literal tag: менять их объявление на новый способ сериализации не нужно.
Ручные `storeUint` и сравнения используют тот же каталог.

Номера адаптеров X1000 — отдельный четырёхбитный enum-подобный каталог
`protocol-kinds.tolk`; они не являются opcode. Названия Tonco, Bidask DAMM/CLMM,
Moon/CLMM, Coffee, STON.fi, DeDust CPMM/Classic, Uranus, StonksPump сопоставлены с
формой payload. Ссылка на ревизию ABI закреплена в JSON. Для адаптера 8 оставлено
`EXTERNAL_8` / `OP_ADAPTER_8_SWAP`: реестр также не устанавливает имя приложения.
Его coin-поле не объявляется «минимальным выходом» без доказательства.
Два callback закрытия маршрута также названы по наблюдаемому удалению состояния;
их оригинальные внешние ABI-имена не установлены. Условие срабатывания каждого
варианта записано в каталоге. Числовых сравнений `opcode == ...` в обработчиках
больше нет.

### Jetton-поля и управляющая логика

- Uranus Wallet V2/V3: `Transfer` → `JettonTransfer`, `InternalTransfer` →
  `JettonInternalTransfer`, `Notification` → `JettonTransferNotification`;
  burn, sell и bounce-варианты также различимы по именам.
- `amount` → `jettonAmount`, `balance` → `jettonBalance`, `from` → `senderOwner`,
  `destination` → `recipientOwner`, `master` → `jettonMaster`, `owner` →
  `ownerAddress`, `payload` → `forwardPayload`, `forwardTon` → `forwardTonAmount`.
  Тонкоины и жетоны в коде больше не скрываются за одинаковым `amount`.
- Storage cursor и сохранённый хвост owner/master названы по назначению.
  Порядок полей, строгость разбора V2/V3 и типы optional не менялись.
- В X1000 названы результаты создания trade-message, изменения очередей,
  проверки opcode и отсутствие продолжения. Убраны одноразовые bool → int → if
  цепочки там, где это доказано BOC; условия source/target сведены к `&&`.
- Имена `ERROR_INVALID_SEQNO`, `ERROR_PENDING_OPERATION_NOT_FOUND`,
  `ERROR_UNSUPPORTED_STORAGE_VERSION`, `ERROR_AUTHORIZATION_OR_REQUEST_VALIDATION`
  соответствуют проверкам X1000. Номер 555 намеренно имеет общее имя: используется
  и при проверке подписи, и при проверке формы запроса/контроллера.
- Во всех группах числовые режимы непосредственных send/reserve-вызовов заменены
  на `SEND_MODE_*` / `RESERVE_MODE_*`; комбинации выражены через `|`.

### Стандартная библиотека: дополнительные принятые замены

| Область | Было | Стало | Проверка |
| --- | --- | --- | --- |
| X1000 | `begin_0F8A7EA5()` и другие hex-prefix ASM | `beginCell().storeUint(OP_JETTON_TRANSFER, 32)` и соответствующие константы | полный BOC совпал |
| X1000 | префиксы заголовка и версии | обычный `storeUint(value, width)` с исходной шириной | полный BOC совпал |
| X1000 | семейство `loadUint*`, используемое для чтения значений | стандартный изменяемый slice cursor, `loadUint`, `loadCoins`, `loadMaybeRef` | полный BOC совпал |
| X1000 | 9 дублирующих dictionary ASM | `@stdlib/tvm-dicts`: get/set/delete/iteration; короткие адаптеры физического ABI | полный BOC совпал |
| Classic | `timestamp`, `current_time`, `self_address`, `pool_address` | `now`, `my_address` из общей stdlib | все затронутые BOC совпали |
| Classic pools | `tuple_cell1`, `tuple_slice0/1/2` | `second`, `first`, `second`, `third` из stdlib | V7/V8/V9 совпали |
| Uranus | пустые payload/address ASM | `createEmptySlice`, `createAddressNone` | все затронутые BOC совпали |
| Uranus | `zeroMintable` | literal `0` | оба master BOC совпали |
| Uranus | `storeArchivedBuilder`, `takeSlice`, BTOS address wrapper | `storeBuilder`, `toSlice`, cast адреса | все затронутые BOC совпали |

`common.tolk` уже автоматически доступна. Отдельного бессмысленного импорта для
`storeCoins` не добавляем. Dictionary-адаптеры сохраняют существующий `cell`-слот,
который может физически содержать null: внутри используется штатный `dict`,
на границе — явные casts. Не добавляем `!`, способный породить проверку/исключение.
Удалены также 9 неиспользуемых приватных кодеков. Публичные method ID не удалялись.

### Отклонённые преобразования и границы

| Попытка | Результат и принятое решение |
| --- | --- |
| `builder.storeTwoZeroBitsCompat()` → `storeUint(0, 2)` во всех местах | изменился BOC X1000; ASM оставлен и переименован, это два нулевых бита, а не opcode |
| Убрать `as unknown` перед проверкой null исторически не-nullable слота | изменился BOC X1000; casts оставлены, иначе компилятор получает другую информацию о типе |
| `findWalletAddress` → обычный typed-map `.get` | изменился BOC CPMM Pool V1; восстановлен исходный checked stack layout |
| `AddressLookup.takeResolution` → `.deleteAndGetDeleted` | изменился BOC CPMM Pool V1; сохранена совместимая операция |

Остаточный ASM состоит в том числе из старых StateInit-кодеков, физических
перестановок/удаления стековых слотов, CALLDICT/CALLXARGS, константных library-ref,
сохранения/восстановления continuation и границ вычисления. Даже `nop` может быть
важен как барьер для компилятора. Стандартная функция, вычисляющая тот же ответ,
не гарантирует такой же байткод. Не заменяем её, если проверка дала расхождение.

Часть временных имён в длинных адаптерах остаётся технической там, где роль поля
не установлена. Это ограничение восстановления, а не подтверждение знания
оригинального исходника. [Инвентаризация](READABILITY-AUDIT.md) показывает реальные
числа замен и оставшегося ASM отдельно по проектам.
